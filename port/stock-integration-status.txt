Fingerprint integration
  Target: libfprint hardware backend -> fprintd -> standard Settings / PAM.
  Existing custom backend has passed one real same-finger acceptance and
  different-finger rejection pair. The isolated libfprint prototype now
  discovers the real sensor but does not implement biometric operations;
  desktop fingerprint unlock remains disabled. The platform discovery patch
  and secure biometric backend still need integration and upstream review.
  The current engineering backend assumes one test database and group 1000;
  it must gain proper per-account ownership, multiple finger identifiers,
  enumeration/deletion, cancellation and reliable error reporting.
  Secure enrollment currently obtains a Gatekeeper token using a setup PIN.
  Standard fprintd does not forward a plaintext account PIN to a driver. That
  authorization boundary needs an explicit design, not a UI wrapper or fake
  virtual sensor. Do not store an account PIN to bridge this gap.
  Verify enrollment/reload, right/wrong finger, no sensor, cancellation,
  deletion, restart, failed authorization and PIN fallback before enabling
  fingerprint authentication. Do not change the existing phone enrollment.
